# TinyLlama 小规模复现实验协议

目标是复现当前仓库实现的三个实验关系：缓存体积与输出质量、带宽与首 token 延迟、量化等级选择与截止时间。环境准备和执行方式见 [README.md](README.md)，机器配置与实测结果保存在各运行批次中。这不是论文原模型、原数据规模和原系统的完整复现。

## 固定实验设计

正式配置为 `mini_repro/profiles/formal4070.json`，验收配置为 `validation4070.json`。文件名保留历史标识，实验条件不绑定特定 GPU 型号。验收配置只验证整个流程，不能用于报告正式实验结论。正式配置不根据验收结果调整阈值。

| 实验 | 数据与条件 | 对照与测量 |
|---|---|---|
| 体积—质量 | 前 20 个 LongChat prompt；512/1024/1536 token；32 token 后续文本；10 个事实 × 开头/中间/末尾 × 3 长度 | 原始 FP16、打包 uniform4/8、CacheGen 1/2/3；逐样本字节数、配对 NLL、逐题答案 |
| TTFT | 前 3 个 prompt × 3 长度 × 0.1/1/10 Gbps | 文本重算、uniform8、CacheGen 2/3；每条件预热 2 次、测量 10 次；固定种子打乱方法顺序；传输/恢复/首 token 分项与总时间 |
| 自适应 | 5 个事实 × 5 条轨迹；1024 token；256 token/块；轨迹倍率 1/0.01；SLO 0.2/0.5 秒 | 剩余预算策略、原静态预算策略、固定 1/2/3 级、文本重算；预热 1 次、测量 3 次；截止时间、选择等级、答案 |

种子为 0。计时重复不增加独立题目数。质量实验生成过程确定，不把重复同一道题当作新样本。NLL 从后续文本第二个 token 开始评分；合成问答按输出首行是否包含答案短语计分。

按长度预先声明描述性质量阈值：相对原始 KV 的平均 NLL 增量 ≤ 0.02，并保留 ≥ 90% 原始 KV 能答对的题目。没有自然文本样本或没有原始正确题时不能通过此门槛。小样本通过门槛不等于统计上证明质量等价；报告需同时显示原始题数、配对差值和正确率。只有通过门槛的配置才可被称为在本代理质量条件下的延迟/体积对比。

## 测量边界

- 使用当前作者编解码器及探索性 TinyLlama 分层参数；编码器没有论文的 anchor/delta 路径。
- TTFT 在本机 socket 上传送真实字节并限速，完整接收后恢复 KV，随后生成首 token；没有服务器间网络或传输—解码重叠。高带宽下应查看实际吞吐。
- 自适应是因果轨迹估计：当前块只使用当前带宽预测剩余块成本，扣除已花费时间及校准的首 token 预留；不会用未来轨迹选择当前等级。它是本机启发式策略，尚未实现论文线上反馈调度器。
- 自适应网络时间为字节/轨迹带宽估计；本机恢复和首 token 时间实测。文本回退使用原始 token IDs，不能当作真实网络文本重分词实验。
- 质量实验中的编码/解码单次时间只是诊断值；正式延迟结论来自 TTFT 重复测量。
- P95 是有限重复样本的描述性统计；重复同一上下文不能替代增加数据集。

## 执行与验收

```bash
python -m mini_repro.reproduce --dry-run
python -m mini_repro.reproduce --profile mini_repro/profiles/validation4070.json
python -m mini_repro.reproduce --profile mini_repro/profiles/formal4070.json
python -m unittest discover -s tests -v
```

默认每次创建 `results/reproduction/<UTC时间>/`，禁止覆盖已有批次。保存配置、命令、源文件/数据/模型 SHA-256、软件/GPU 信息、每次观测和日志，再生成 CSV 与 Markdown 报告。失败保留已完成结果并标记状态，不能把未完成批次称为成功。

验收包括：配置/覆盖保护/失败状态测试、计时重复与顺序测试、剩余预算与首 token 预留回归测试、配对质量门槛测试，以及本机 GPU 完成一遍验收配置。正式配置的结果必须实际运行后才能报告；不能用验收批次代替。

结果归档只纳入经过完整性核对的正式批次，机器环境与结果放在同一目录；验收、冒烟、中断及零散调试记录留在本机。后续补论文差分编码、解码流水线或换 7B 模型需要另一个实验协议。
