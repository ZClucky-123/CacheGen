## 样本与重复的区别

质量：2 个独立 LongChat 源文档×2 长度＝4 个续写条件；2 个事实×3 位置×2 长度＝12 个受控条件；4 个完整 TQA 问题。每条件比较六方法，共 120 条逐方法观测。

TTFT：同 2 源文档×2 长度×3 带宽×4 方法×3 正式重复＝144 次；48 次预热另存且排除。自适应：3 个事实×2 轨迹×6 策略×2 重复＝72 次/配置，共四配置 288 次；另有 144 次预热。轨迹、长度、位置、方法和计时重复均不是新的独立问题；自适应事实包含质量组的前两个事实。

## TTFT、网络与缓存正确性

CacheGen 3 在 6 个长度/带宽组合中，2 个组合的中位 TTFT 优于优化后的文本重算，6 个组合优于 Uniform8。速度比较仍须同时检查对应长度的质量门槛；不能由这些数值宣称论文级收益。

10Gbps 目标、8MiB payload 校准实测 8.924–8.972Gbps；小包开销更明显。实际吞吐逐次保存，没有将目标 10Gbps 写成实测 10Gbps，也没有限速 SSH 主网卡。

缓存检查在 4 个真实文档/长度条件上比较完整 forward、只投影末位置的实现、raw KV 复用、重复生成、自然续写、分块拼接及上下文相关文本重算。raw logits 最大误差 0.0195312；多 token greedy 输出一致，原缓存未被污染。另对所有压缩方法检查形状/FP16/有限值与质量，GPU 测试逐符号覆盖 257-token 尾块和解码缓冲区扩容。

全部正式观测真实执行 GPU 推理与实际字节 socket 传输；网络为本机限速模拟，不是跨服务器 WAN。TTFT 为完整接收后恢复，adaptive 为逐块串行；没有传输—解码流水线。trace_estimate 模式仅实现，没有混入本批次。

文本采用 UTF-8＋显式 token 修补元数据，接收端实际重分词，framing 与 patch 全计入字节。离线 prefill、编码及自适应准备分别保存，作为每次上下文准备的注记，不能按计时重复数重复累加。

## 直接运行较大规模

两份 larger 配置只执行了数据/窗口/资源/绘图预检，未自动启动正式测量，见 [Mistral 检查](../../../docs/reproduction/larger-mistral-preflight-20261024.json)与 [TinyLlama 检查](../../../docs/reproduction/larger-tinyllama-preflight-20261024.json)。Mistral 4096-token 矩阵采用原 FastChat 8bit 权重，预估约 15.13GiB GPU、20.21GiB 主存；实际预检会重新核对可用资源。建议至少 2GiB 额外磁盘，预计数小时，取决于带宽与矩阵。TinyLlama 受 2048 窗口和仅 7 个短 TQA 的限制。这不是单张 4090 的官方 70B 配置。

```bash
python3 -m experiments.background start --name mistral-larger-new -- \
  --config experiments/configs/larger-mistral.json --run-id larger-new
python3 -m experiments.background status --name mistral-larger-new
python3 -m experiments status mistral --run-dir results/mistral/larger/larger-new
python3 -m experiments.background start --name mistral-larger-resume -- \
  --resume results/mistral/larger/larger-new
```

tmux 在服务器持有进程；关闭终端可继续。`tmux -L cachegen attach -t <会话名>` 查看，Ctrl-b d 脱离。恢复前核对配置、源码、数据、模型与环境；同 GPU 使用共用排他锁，版本变化必须新批次。完整操作见 [运行指南](../../../docs/reproduction/SHARED_FRAMEWORK.md)。
