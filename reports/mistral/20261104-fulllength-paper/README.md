设置：

- **数据：** 不截断，KV 长度 8559–9288 token。概率表由 ID 30–49 统计，只用上下文；测试 ID 0–19，与统计集不重叠。
- **体积：** 概率表离线共享，不计入包内（每种配置的表文件 67 MB，只需存一份）。
- **对照：** 之前两轮 ID 0–19 的同流程结果（问题的 KV 现算）。那些方法没有差分，概率表随包发送并计入体积（约 2 MB）。本轮原始 KV 的回答与之前 20/20 相同。
- **缩放范围：** 论文没写明 bin 的单位。这里把差分向量按最大绝对值缩放到这个范围，再按 0.5/1/1.5 取整。这是我们的解释，范围是看过试跑体积后定的，也不是搜索出的最优值。

## 判断

- **按我们的解释，论文方法没有比之前的方案更小。** 它全对的最小点是 215.6 MB，相对 8 bit 小 2.72 倍；论文 Table 1 是 0.283（3.5 倍）、准确率 0.98。同样全对，无差分的统一 ±5 + 算术编码只要 144.1 MB，作者代码等级 1 只要 154.5 MB。
- **体积接近 0.283 时准确率偏低，但证据不强：** 差分不分层在 0.283 处为 18/20，区间上限 0.972 略低于 0.98；差分 + 分层在 0.293 处为 17/20。范围 3 到 5 之间没有测，真正的下降点可能在这之间。
- **差分：没有看到行为上的收益。** 体积几乎相同时（215.6 对 217.8 MB），差分的 MSE 低约 28%（0.112 对 0.155），但答对、逐字相同和正常结束都打平（20、10、11）。同一范围下差分的体积大 15–19%。范围 3 对范围 5（172 对 184 MB）时，差分 MSE 更低，答对却是 17 对 20（p = 0.25），逐字相同 1 对 7（p = 0.07），所以 MSE 不能预测回答质量。
- **分层：没有看到收益。** 同一范围下，分层比不分层大 3–4%，MSE 更高；答对 20 对 19、17 对 18，差异不显著（p = 1.0）。这组宽度的平均值是 1，它只是在层间重新分配精度，没有整体降低精度。
- **同体积下不如作者代码等级 3：** 都是约 252 MB，MSE 0.052 对 0.035，逐字相同 13 对 18（p = 0.125），正常结束 14 对 19（p = 0.0625）。方向一致，但不显著。

**论文结论的复现情况：** “小约 3.5 倍且准确率基本不掉”这个结果成立，但目前靠的是作者公开代码的做法（没有差分），即等级 1 的 3.8 倍；论文文字描述的差分编码没有表现出收益。论文里相对 4 bit 的质量差距仍未复现：4 bit 这里也是 20/20。

## 可能的原因（未验证）

- **8 bit 锚点的开销：** 每 10 个 token 有一个 8 bit 锚点。按之前 6.08 bit/值估算约 45 MB，差分和不差分两组都要付。它可能是不差分范围 5（184 MB）大于统一 ±5 + 算术编码（144 MB）的主要原因之一。但两者的量化精度和概率表都不同，数字接近也可能是巧合。
- **差分的数据基础：** 之前 4K 实验里，差分后 K 的方差约降到 0.51 倍，V 反而升到 1.53 倍，所以只有 K 可能受益。

## 局限

- 缩放范围是我们的解释。论文的 bin 单位如果不同，结果可能改变，所以这里不能断定论文方法本身无效。
- 只有 20 篇、一个任务、一个模型，判分是字符串包含。配对检验共 16 组，没有做多重比较校正。
- 不差分对照保留了锚点和分层，不是干净的“无差分方案”；干净的对照是之前的统一 ±5 + 算术编码，但它走另一条代码路径（作者编码器，按层和 token 缩放，概率表随包）。
- 符号流以外的部分约占包的 11–19%（由 `stream_bytes` 算出），主要是长度字段，来自本地每 96 token 一段的做法，两条路径都有。
- 准确率高不代表回答质量没变：作者代码等级 1 答对 20/20，但与原始回答逐字相同的只有 6/20。
