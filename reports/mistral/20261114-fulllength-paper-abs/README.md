# 2026-11-14 全长 LongChat：论文差分方法的补充检验

目的：接着[上一轮](../20261104-fulllength-paper/README.md)，补全差分的检验。一是补测缩放范围 4，找出准确率开始下降的点；二是换一种 bin 单位解释，把 0.5/1/1.5 直接当作 KV 原始数值的单位，不按向量缩放。这是对论文文字最直接的读法。

运行：RTX 4090 D，提交 `d6b6626` 加未提交的 `tools/full_length_paper.py`（SHA256 前缀 `588d454884ba14d6`，在上一轮版本上新增 6 种配置和 `--configs` 选项）。概率表统计约 27 分钟，测试约 34 分钟，退出码 0，共 140 条记录；另有 1 篇文档的试跑，记录在 `pilot/`。下载文件的 SHA256 与服务器一致。统计由 [analyze.py](analyze.py) 生成，合并了上一轮的记录，输出在 [summary.json](summary.json)。

其他设置与上一轮相同：甲端只压缩上下文的 KV，乙端现算问题的 KV；概率表由 ID 30–49 统计，离线共享，不计入包内；测试 ID 0–19。本轮没有逃逸符号。

## 判断

- **按原始单位读，论文方法更接近论文结果，但仍没有超过无差分方案。** 差分 + 分层为 190.1 MB、20/20，相对 8 bit 小 3.09 倍；论文是 3.5 倍、准确率 0.98。同样全对，统一 ±5 + 算术编码只要 144.1 MB，作者代码等级 1 只要 154.5 MB。
- **差分仍然没有收益，原始单位下保真度反而更差。** 不差分只要 180.6 MB（小 5%），准确率同为 20/20，逐字相同 10 对 3（p = 0.016），正常结束 15 对 6（p = 0.012）。和体积相同的作者代码等级 2 比，差分 + 分层逐字相同 3 对 9（p = 0.07），也偏低。
- **原始单位下，浅层的精度很关键。** 把前三分之一层从 0.5 放宽到 1（即差分不分层）后，答对从 20/20 掉到 1/20（p < 0.0001），输出基本是乱码，但整体 MSE 反而最低（0.068）。这支持论文“浅层更敏感”的说法。但不分层同时也让浅层变粗，所以这只说明浅层需要更细，不说明分层在体积相同时更好。原因未验证；一个可能是浅层的数值本身很小，整体 MSE 被深层的大数值主导。
- **范围 4 的结果没有改变上一轮的结论：** 差分 + 分层在 196.4 MB 时为 19/20；按向量缩放的解释下，它全对的最小点仍是范围 5 的 215.6 MB。

## 两轮合起来的结论

两种 bin 单位解释、五个缩放范围下，论文文字描述的差分编码都没有带来体积或质量上的收益。同样全对时，最小的方案都没有差分：统一 ±5 + 算术编码（144 MB）和作者代码等级 1（154 MB），相对 8 bit 小 3.8–4.1 倍。分层只在原始单位解释下有用，而且作用是让浅层更细，没有证明它能在体积相同时更好。

## 局限

- 只有 20 篇、一个任务、一个模型，判分是字符串包含。两轮的配对检验没有做多重比较校正。
- 范围和宽度都是人工选的，不是搜索出的最优值。
- 不差分对照保留了每 10 个 token 一个 8 bit 锚点；对照方案走作者编码器，概率表随包。两条路径的包格式不同，体积比较只能看大的差距。
