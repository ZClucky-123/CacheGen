# 可迁移实验工作区

用户要求所有文件实体归入 `/home/aaa/CacheGen`，仅该仓库上传 GitHub，并允许为后续实验的兼容性和扩展性重构。按此授权直接在指定工作区执行。

## 结构与边界

- `experiments/<family>/`：每组实验代码和配置。现有 Mistral 收入此处；`mini_repro` Python 导入路径保留。
- `experiments/registry.json`：实验名称、描述、执行参数列表与结果目录。标准库入口 `python -m experiments list|run|status` 按注册表调度，新增实验无需修改调度器。
- `results/<family>/<batch>/`：原始记录，保留已成功及失败批次。新运行使用唯一批次、配置快照及 GPU 排他锁。
- `reports/<family>/`：现有报告、图表和交付包。通过校验的 20261024 报告包及成功原始批次入库；依赖、模型、编译缓存只在本机。
- `.local/`：本机缓存、迁移备份及记录。`.venv`、CUDA 保留原位，避免重装及重下载。
- `mistral_repro` 及实验目录内的旧 `runs`、`deliverables`、缓存入口使用仓库内相对链接兼容；`/home/aaa` 不保留散落文件。已有 `/root/cachegen-repro` 链接重新指向仓库内兼容入口。

## 选择

仅移动文件无法解决绝对路径；全面改写模型评估会扩大指标变更风险。因此采用共用路径发现、注册表和环境脚本，保持现有编解码与评分算法。用户授权目录大改；采用此实现方式由执行者判断。

所有活动入口根据脚本位置确定仓库位置，支持环境覆盖结果、报告和缓存目录；从含空格路径及非仓库当前目录调用仍应有效。旧批次元数据及源码快照作为历史证据保持字节不变。

## 验证与发布

先测试迁移路径、无结果状态、自定义结果位置、第三方新增注册项与无副作用 dry-run，再实现；运行原有全套及 Mistral 测试，校验所有历史原始记录及交付清单。备份已有暂存区后，仅取消 CUDA 的暂存，明确添加源码、文档与已验证结果，检查 Git 对象尺寸和敏感凭据后上传现有远端分支，不改写远端历史。
