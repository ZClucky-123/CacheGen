# 2026-11-02 全长 LongChat：算术编码与更低精度

目的：接着[全长质量验证](../20261102-fulllength-qa/README.md)，分清优势来自算术编码还是分层，并找到准确率下降的位置。这轮没有运行按论文文字实现的新路径，方法里都没有差分。

运行：RTX 4090 D，提交 `d6b6626` 加未提交的 `tools/full_length_qa.py`、`tools/full_length_ac.py`，用时约 43 分钟，退出码 0。下载文件的 SHA256 与服务器一致。统计由 [analyze.py](analyze.py) 生成，输出在 [summary.json](summary.json)。

设置与上一轮相同：ID 0–49，不截断，贪心生成 20 token，指标是回答是否包含标准话题。概率表都按上下文统计、随包发送并计入体积。档数 B 对应最大符号 B÷2−1，如 16 档为 ±7。层组是 K 的第 0–9、10–19、20–31 层和 V 的第 0–1、2–31 层。

## 判断

准确率满分的最小方法是 `layer_a`。相对 8 bit 小 4.31 倍，相对 4 bit 小 2.15 倍。这些倍数只针对这个任务和这 50 篇。

| 从 | 到 | 缩小倍数 | 来源 |
| --- | --- | ---: | --- |
| 8 bit | 4 bit | 2.00 | 降低精度 |
| 4 bit | `ac_b16` | 1.68 | 算术编码 |
| `ac_b16` | `ac_b12` | 1.22 | 继续降低精度 |
| `ac_b12` | `layer_a` | 1.06 | 分层 |

- **算术编码贡献大，分层没有净收益。** 准确率相同时，分层只小约 5–6%（`layer_a` 对 `ac_b12`，`layer_b` 对 `ac_b10`），但回答保真度明显更差（见下节）。综合看，`ac_b12` 比 `layer_a` 更值得作为对照：144.0 MB，相对 8 bit 小 4.07 倍，相对 4 bit 小 2.04 倍。
- **准确率下降的位置：** 统一精度下，±5 全对，±4 掉到 0.90，±3 掉到 0.82，±2 基本失效。分层把精度压到 ±2（`layer_d`）同样会严重掉分：相对 `ac_b8` 只小 14%，准确率显著更低（作者组 22 对 41，p < 0.0001）。
- **没有差分也达到了论文水平：** 论文 Table 1 是 0.283、准确率 0.98，这里 0.233、准确率 1.00。

## 二次分析

由 [deep_analysis.py](deep_analysis.py) 生成，输出在 [deep_analysis.json](deep_analysis.json)。这些分析都是看到结果后才做的，配对检验没有做多重比较校正，应视为探索性结果。

**保真度。** 准确率满分时看不出差异，所以另看两个指标：回答是否与原始 KV 逐字相同、模型是否正常结束（原始 KV 为 50/50）。

| 比较（作者组） | 体积 | 逐字相同 | 正常结束 |
| --- | --- | ---: | ---: |
| `layer_a` 对 `ac_b12` | 136 对 144 MB | 27 对 44，p = 0.0002 | 32 对 50，p < 0.0001 |
| `layer_b` 对 `ac_b10` | 117 对 124 MB | 6 对 29，p < 0.0001 | 11 对 43，p < 0.0001 |
| `layer_a` 对 `ac_b10` | 136 对 124 MB | 27 对 29，p = 0.81 | 32 对 43，p = 0.003 |

问题不压缩组方向相同：`layer_a` 对 `ac_b12` 逐字相同 3 对 13（p = 0.006），正常结束 2 对 13（p = 0.003）。

异常：`layer_a` 每层精度都不低于 `ac_b10`，MSE 也更低，正常结束却更少。作者的分层档位 1 和统一 16 档相比，在问题不压缩组也更差（正常结束 14 对 28，p = 0.0005），但在作者组没有差异。原因未查明，也还没有排除混合精度路径的实现问题；MSE 的顺序符合预期，只能说明重建误差的总量合理。

**字节构成（估算）。** 按线上格式估算概率表、缩放系数和长度字段，其余算作编码符号。

| 方法 | 总体积 | 符号 | 长度字段 | 概率表 | 缩放系数 | 符号 bit/值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 8 bit + 算术编码 | 504.5 MB | 445.1 | 24.6 | 33.7 | 1.1 | 6.08 |
| `ac_b16` | 175.3 MB | 147.2 | 24.6 | 2.2 | 1.1 | 2.01 |
| `ac_b12` | 144.0 MB | 116.6 | 24.6 | 1.7 | 1.1 | 1.59 |
| `layer_a` | 136.4 MB | 108.4 | 24.6 | 2.2 | 1.1 | 1.48 |
| `ac_b8` | 99.8 MB | 72.8 | 24.6 | 1.2 | 1.1 | 1.00 |

- 算术编码的收益随精度变化：8 bit 从 8 降到 6.08 bit/值，4 bit 从 4 降到 2.01，3 bit 从 3 降到 1.00。
- 除 8 bit 外，长度字段约占 14–35%。这是本地改成每 96 token 一段带来的；如果按作者原版每 256 token 一段，`ac_b12` 约 129 MB，但低精度下是否仍不溢出没有验证。
- 只看符号，8 bit 相对未编码 8 bit 约 0.76，仍高于 Fig. 15 估读的 0.58。

**失败的结构。**

- **下降点附近结果不稳定：** 作者组 `ac_b10` 失败的 5 篇里只有 1 篇在 `ac_b8` 也失败。第 11 篇在 ±4 答错、在 ±3 答对。所以几个百分点的准确率差异不宜过度解读。
- **错误主要是记混话题：** 下降点附近的 5 种方法合计 141 次错误，115 次（82%）说成了标签列表里的其他话题，26 次是列表外的说法。±2（`ac_b6`）则不同，作者组 26 篇基本是空输出。
- **没有混到第二个话题：** 115 次里只有 2 次说成第二个话题。"The benefits of reading for pleasure" 出现 29 次，占 25%，明显高于它在全部非首位标签中约 4% 的占比。这些计数跨方法和分组合并，彼此不独立。
- **文档难度不均匀：** 在 `ac_b10`、`layer_b`、`layer_c`、`ac_b8` 与两个分组的 8 个组合里，第 9、28 篇有 7 个失败，25 篇从未失败。上下文长度（8.6–9.3K 范围内）与失败没有明显关系。

## 局限

- 分层方案是我人工定的几组，不是搜索出来的最优方案，分层的收益可能被低估。
- 配对检验没有做多重比较校正，分层和统一精度的体积也不完全相同，只能在相邻点之间比较。
- 只有一个任务、一个模型、50 篇，判分方式也不同于作者代码的 `gpt-3.5-turbo`。
- 8 bit + 算术编码的相对体积 0.860 与 Fig. 15 估读的约 0.58 差距较大，其中随包概率表约占 0.06，其余原因未查明。
- 问题不压缩组在低精度下掉分更多，原因未查明。
