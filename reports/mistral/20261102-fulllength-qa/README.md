# 2026-11-02 全长 LongChat 质量验证

目的：不截断上下文，检验基线和作者代码的体积与质量。这轮没有运行按论文文字实现的新路径。

运行：RTX 4090 D，提交 `d6b6626` 加未提交的 `tools/full_length_qa.py`（SHA256 前缀 `53653b28`），用时约 43 分钟，退出码 0。下载文件的 SHA256 与服务器一致。统计由 [analyze.py](analyze.py) 从 [records.jsonl](records.jsonl) 生成，输出在 [summary.json](summary.json)。

设置：LongChat ID 0–49，KV 长度 8588–9317 token，贪心生成 20 token。指标是回答是否包含标准话题（忽略大小写和标点）。这轮没有调参。

- **作者组：** 与作者 `main.py` 相同，KV 覆盖除最后一个 token 外的整个提示，问题也被压缩。这是主要结果。
- **问题不压缩组：** KV 只覆盖对话，问题不压缩，用于诊断。

体积和相对值取自作者组。95% Wilson 区间：50/50 为 [0.929, 1.000]，41/50 为 [0.692, 0.902]，28/50 为 [0.423, 0.688]。ID 0–19 单独统计时，作者组 3 bit 为 18/20，问题不压缩组为 10/20，其余方法都是 20/20。

配对精确检验（作者组）：档位 1、档位 2、4 bit 各自与 3 bit 比较，都是 9 篇只有前者答对、0 篇只有 3 bit 答对，p = 0.0039。3 bit 在两组之间的差异为 14 对 1，p = 0.001。

## 判断

- **体积：** 相对 8 bit，档位 1/2/3 小 3.80/3.08/2.33 倍，准确率都是满分。论文 Table 1 是小 3.5 倍、准确率 0.98。
- **相对 3 bit：** 作者代码更小且更准确，差异显著。
- **相对 4 bit：** 没有复现论文的质量差距。4 bit 也是 50/50，论文估读约 0.90，这个读数在我们的区间之外。所以按质量相同计算，作者代码相对 4 bit 小 1.54–1.90 倍。
- **问题是否被压缩：** 这不是 4 bit 不掉分的原因，因为两组 4 bit 都是 50/50。3 bit 在问题不压缩时反而掉得更多，原因未查明。

## 局限

- 这个任务有天花板：作者代码三档都是满分，测不出还能再压缩多少，所以 1.54–1.90 倍只是下限。
- 只有一个任务、50 篇文档；论文是 200 篇。论文判分用 `gpt-3.5-turbo`，这里用字符串包含。
- 没有测基线加算术编码。档位 1 的精度和 4 bit 相近（16/16/12 档对 16 档），它的优势可能主要来自算术编码，这只是推断。
